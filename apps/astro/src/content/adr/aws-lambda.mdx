## Context

Our application has several background processing tasks that don't require constant server resources. We're looking for a more cost-effective and scalable solution for these intermittent workloads.

## Decision

We are evaluating AWS Lambda for our serverless computing needs. Lambda's event-driven, pay-per-use model appears well-suited for our background processing tasks, API endpoints with variable traffic, and scheduled jobs.

## Consequences

- Reduced operational costs for intermittent workloads
- Automatic scaling based on demand without provisioning servers
- Need to refactor some existing services to fit the serverless paradigm
- Potential cold start latency for infrequently used functions
- Improved isolation between different parts of our application
