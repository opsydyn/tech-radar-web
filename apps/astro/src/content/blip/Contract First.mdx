## Context

Contract-first delivery helps teams coordinate API changes before implementation details leak across service boundaries. The approach is useful for static documentation, generated clients, and clearer collaboration between producers and consumers.

## Decision

Treat contract-first design as a proposed technique for API-facing work where integration risk is high or multiple consumers depend on stable semantics.

## Consequences

- API contracts become reviewable artifacts before implementation is complete.
- Teams need discipline to keep generated artifacts and implementation aligned.
- Lightweight internal APIs may not need the full ceremony.
