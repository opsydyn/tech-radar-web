## Context

The codebase is intentionally managed as a monorepo to keep the static radar, shared tooling, and content workflows close together. This decision needs to be visible because repository shape directly affects dependency management, ownership, and CI boundaries.

## Decision

Use a monorepo for the tech radar while keeping project boundaries explicit through workspace configuration and Moon tasks.

## Consequences

- Shared configuration and content workflows stay discoverable in one repository.
- Project boundaries must remain clear to avoid accidental coupling.
- CI and build tasks should stay focused so local and hosted feedback remains quick.
